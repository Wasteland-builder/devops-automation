你说得非常对，**生产环境确实不会用宝塔面板**。宝塔更适合个人开发者或内网测试环境，放在公网生产环境会引入额外的安全风险和性能开销。

既然你选择原生Linux操作，这是非常专业且正确的决定。你的服务器配置（2核4G，Ubuntu 24.04 LTS）完全可以跑得很稳。

买完服务器后，我来给你整理一套**原生Linux生产环境的标准搭建流程**，帮助你以最干净、最可控的方式把网站跑起来。

---

### 🚪 第一步：安全登录服务器（不要用默认密码）

拿到服务器的IP和root密码后，**不要直接密码登录**。建议立刻做两件事：

1.  **创建普通用户并授予sudo权限**（禁止直接使用root）：
    ```bash
    adduser deploy              # 创建部署用户
    usermod -aG sudo deploy     # 加入sudo组
    su - deploy                 # 切换到该用户
    ```

2.  **配置SSH密钥登录，并关闭密码登录**（这是生产环境最基本的底线）：
    - 本地电脑生成密钥对：`ssh-keygen -t ed25519`
    - 将公钥上传到服务器：`ssh-copy-id deploy@你的服务器IP`
    - 修改 `/etc/ssh/sshd_config`，设置 `PasswordAuthentication no`，然后 `systemctl restart sshd`。

---

### 🧱 第二步：安装核心运行环境（LEMP 栈）

以 Ubuntu 24.04 为例，搭建**最经典、资源占用低的 Nginx + MySQL + PHP** 组合：

**1. 更新系统并安装基础软件：**
```bash
sudo apt update && sudo apt upgrade -y
sudo apt install nginx mysql-server php8.3-fpm php8.3-mysql php8.3-cli php8.3-curl php83-zip php8.3-xml php8.3-mbstring -y
```

**2. 为 PHP 和 MySQL 做生产环境调优（针对你4G内存）：**
- **MySQL调优**：编辑 `/etc/mysql/mysql.conf.d/mysqld.cnf`，找到 `innodb_buffer_pool_size`，把它改成 `1G`（给数据库留足缓存，别用默认值）。
- **PHP调优**：编辑 `/etc/php/8.3/fpm/php.ini`，调整 `memory_limit = 256M`，`upload_max_filesize = 20M`（根据你博客图片大小调整）。
- 修改完后重启：`sudo systemctl restart mysql php8.3-fpm`。

**3. 配置 Nginx 网站：**
在 `/etc/nginx/sites-available/` 下创建你的配置文件（例如 `blog.conf`），指向你的项目目录（比如 `/var/www/blog`），然后软链接到 `sites-enabled/`。检查配置无误后 `sudo nginx -t` 再 `sudo systemctl reload nginx`。

---

### 🔥 第三步：开启防火墙（UFW）

生产环境必须开防火墙，只留必要的端口：

```bash
sudo ufw allow 22/tcp    # SSH端口
sudo ufw allow 80/tcp    # HTTP
sudo ufw allow 443/tcp   # HTTPS（后面要配SSL）
sudo ufw enable
sudo ufw status          # 查看生效规则
```

---

### 🔒 第四步：配置 HTTPS（免费SSL证书）

千万别买付费SSL，用 **Let's Encrypt** 官方工具 `certbot` 一键申请免费证书（有效期90天，支持自动续期）：

```bash
sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d 你的域名.com
```

跟着提示输入邮箱，certbot 会自动帮你修改 Nginx 配置，把 HTTP 跳转到 HTTPS。

---

### 📁 第五步：上传代码与权限管理

- **目录结构建议**：把网站代码放在 `/var/www/你的域名/` 下。
- **权限原则**：文件权限设为 `644`，目录权限设为 `755`。网站文件所有者设为 `www-data:www-data`，但你的 `deploy` 用户需要能读写，记得把 `deploy` 加入 `www-data` 组，并用 `setfacl` 或 `chown` 调整好。

---

### 📊 第六步：日志与监控（生产运维标配）

- **日志切割**：安装 `logrotate`（系统自带），确认 `/etc/logrotate.d/nginx` 和 `mysql` 配置正确，防止日志文件把硬盘撑爆。
- **资源监控**：安装 `htop` 和 `iftop`，方便实时看CPU内存和网络流量：`sudo apt install htop iftop`。

---

### 🧹 对比宝塔，原生操作的优势

- **透明可控**：每一行配置、每一个进程都在你眼皮底下，没有黑盒操作。
- **资源占用低**：没有面板常驻进程，4G内存能省出近1G给业务使用。
- **安全基线高**：不会因为面板漏洞被一锅端（历史上宝塔出现过多次RCE漏洞）。
