# 国联民生生产麒麟服务器内存告警

**📅 发生时间：** 2026-08-31 10:15
**🛠️ 处理人员：**张斌
**🔴 严重等级：** P2（监控告警）

---

## 一、 故障现象

- **告警信息：** 信创麒麟服务器触发内存使用率超过 95% 的 Warning 告警。
- **业务影响：** 
  - 无业务影响，该服务器只部署了运维平台

---

## 二、 处理过程

### 1. 应急恢复

- **查看内存整体使用情况：**

  ```bash
  free -h
  # 输出示例：/dev/sda1  /data  98%
  ```

- **定位内存占用大户：**

  bash

  ```sh
  top
  # 然后输入 M
  ```

- **发现罪魁祸首：**
  找到内存占用最多的进程——kylin_kms_daemo。这是银河麒麟操作系统自带的 KMS（密钥管理服务）激活守护进程（对应的服务名是 kylin-kms-activation.service），主要负责系统许可证的自动激活和授权验证。

  正常情况下，这个激活进程只占用几 MB 内存，而它现在吃掉了系统接近一半的物理内存。这是银河麒麟系统的一个已知内存泄漏 Bug（通常是因为该服务在尝试连接 KMS 激活服务器失败时，会不断重试且不释放之前的资源，导致内存持续膨胀）。.

- **解决方案：**

  ####  **临时释放内存（立即生效）**

  #### **1. 临时解决**

  手动重启该服务，可以立刻把这 6.4G 内存释放回系统：

  ```sh
  systemctl restart kylin-kms-activation.service
  ```

  #### **2. 彻底解决（推荐）**

  - **打补丁升级**：这是麒麟系统早期的已知缺陷，建议执行 `sudo apt update && sudo apt upgrade` 更新系统补丁，或者去麒麟官网下载最新的“内存泄露修复补丁”。

  - **限制服务资源**（如果无法升级）：
    修改服务配置文件，限制其最大内存使用量，防止它再次撑爆系统：

    ```sh
    # 1. 编辑服务配置
    systemctl edit kylin-kms-activation.service
    
    # 2. 在空白处添加以下内容并保存
    [Service]
    MemoryMax=128M
    MemorySwapMax=0
    
    # 3. 重新加载并重启服务
    systemctl daemon-reload
    systemctl restart kylin-kms-activation.service
    ```
